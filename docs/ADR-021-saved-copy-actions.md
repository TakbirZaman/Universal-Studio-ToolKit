# ADR 021: Explicit saved-copy handoff and process-another actions

Date:2026-10-20.
Status: Dart/application checks pass locally; new Windows/Android adapters require platform compilation and device/desktop acceptance.

Saved-copy actions are explicit user gestures after an export. Capabilities determine whether Open, Share or Show in folder appears. No copy is opened or shared automatically, and receipt locations never become shell command text. Process another clears source selections, saved feedback and one-off rotations/crops/page overlays while preserving useful dimensions/format/limit settings. Existing exports remain unchanged.

Android uses only content URIs registered after an actual verified create-copy write in the current Activity session. A bounded128-entry receipt map retains MIME, byte count and SHA-256, not document contents. Open/share rereads the copy on the existing single worker and compares bytes/digest before granting temporary read-only URI access. The system chooser handles recipient choice; no write grant, broad storage permission, telemetry or upload service is added. VIEW/SEND package-visibility queries allow targeted capability checks. Old receipts after activity recreation are deliberately unavailable. The Activity worker shuts down gracefully after queued writes complete.

Windows uses UTF-8→UTF-16 conversion, absolute regular-file/extension checks, association lookup and documented ShellExecuteW/SHOpenFolderAndSelectItems APIs behind a narrow channel. COM is initialized by the existing runner. Linux uses system xdg-mime/xdg-open only in a graphical desktop session, a bounded association-query timeout, and a single absolute argument without a command shell. It does not offer an unimplemented Linux Share action. Before a desktop handoff, Dart compares the current bounded file stream against the actual prepared export and rejects changed/linked copies. A successful request means handed to the system, not proof a viewer finished opening the document.

The same presentation is reused for primary studio exports, recipes/batch items, PDF-page PNGs, PDF text and OCR text. Exact receipt bytes are retained independently of later page navigation and cleared when text/settings change. Capability/format/URI/path/changed-file tests and responsive controls pass; actual saved pack/signature workflows exercise process-another and verify existing files remain. OS action adapters are substituted in widget tests. Real Windows/Linux viewer launch, Android grant/chooser behavior and activity recreation remain acceptance work, not inferred from those tests.

No new third-party dependency or runtime asset is introduced.
