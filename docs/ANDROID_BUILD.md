# Android development builds

Target: arm64-v8a, API 24+. This is a build configuration, not tested device compatibility.

Use Flutter 3.47.7, Rust 1.99.0 (aarch64-linux-android target), JDK 17, Android platform/build-tools 36, and NDK 28.2.13676358. The current staging/build script requires a Linux x86-64 host.

Download the non-V8 `pdfium-android-arm64.tgz` from the bblanchon/pdfium-binaries `chromium/8076` GitHub release. Set UST_PDFIUM_ANDROID_ARCHIVE to that local archive and ANDROID_HOME to the SDK, then run `bash scripts/build_android.sh`. The staging script checks SHA-256 b7a6919dc130dfdf7e409bd1762ed2a306408c4faee1173668837fc446217bf7 before extracting it. Downloads occur only in the explicit development workflow, never application document processing.

All collected notices are packaged as Android assets. Native libraries and copied assets are generated build inputs, excluded from Git. The workflow uses read-only repository permissions and short-lived development artifacts.

Release signing is not configured. The release APK is labelled unsigned and is not an installable production release. Configure your own private signing key outside the repository and back it up securely. Never commit keystores or passwords. Losing the signing key can prevent updates to installed releases.

## Local-data backup policy and installable development release

Android explicitly opts out of backup, declares legacy and Android 12+ exclusion rules for all app-data domains, and uses a no-data backup agent for key/value and full-backup callbacks. This protects local drafts/settings from the standard app backup paths; actual OEM/transport behavior still needs device testing. Existing backup copies are not erased by this configuration. User-selected exported copies remain under their chosen destination's control. The app does not implement cloud synchronization or uploads.

The build additionally signs the optimized release-mode APK with an explicit ephemeral development identity generated by keytool, naming it `universal-studio-android-arm64-development-release.apk`. This is an installable **development** build, not production signing. It has release-mode behavior and must not request Internet or broad-storage permissions; compiled-manifest checks enforce that alongside backup flags/rules. Debug-mode APKs retain Flutter debugging permission separately. No keystore or private key is copied to artifacts or committed.

The public development passwords are used only for this disposable development key. Its private temporary directory is removed on normal success or failure; the key is never part of dist/. The signing step does not assume Gradle uses $HOME/.android/debug.keystore. Keep production signing separate, back up its key securely, and never use a development identity for a production release. CI development keys can differ between builds, so an update may require uninstalling and lose app-local data; save needed document copies first.
