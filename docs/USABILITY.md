Implemented UI design decisions: native controls with semantic text labels; tooltip labels on icon buttons; no colour-only success state; light/dark Material themes; nonfixed card heights and scrollable pages; 52px primary controls; source and actual result size separate; original unchanged message; errors beside processing controls; no fake progress percentages; no destructive overwrite control; no mandatory onboarding.

Remaining gates: 200% scaling on every tool, narrow-window and long-filename checks, contrast measurement for custom accent text, complete localization extraction, screen-reader traversal, focus restoration, keyboard shortcuts, drop targets, Android reachability, font/glyph availability, reduce-motion behavior, user observation on all five scenarios. Current strings are English and require extraction into ARB before localization-ready status.


Keyboard shortcuts now cover choose files (Ctrl+O), prepare preview (Ctrl+Enter) and save a copy (Ctrl+S), with visible desktop hints. Save actions guard against overlapping exports while a destination dialog/write is pending. A keyboard-only missing-input test and representative light/dark text/icon contrast checks are entering verification. These do not establish complete screen-reader, focus-order or all-state contrast coverage. Dark studios retain distinct high-contrast accents alongside labels and icons.

Experimental OCR heuristic review (2026-10-17): Scan Documents exposes “Read printed text from selected page” only with the local engine and verified assets. A selected page preview, language selector, explicit read action, editable result, actual UTF-8 save validation and original-unchanged message explain the flow. Indeterminate named states replace fictional percentages; accepted cancellation waits for preparation/cleanup. A real-engine widget test verifies text reaches the editor and can be corrected. This is not observed user testing. Multi-page OCR, reading-order/layout preservation, screen-reader traversal, text scaling and broader document accuracy remain to be evaluated.

Physical-photo heuristic review: a print-size switch reveals mm/DPI fields while retaining separate pixel settings. Invalid DPI is reported near the field. Real Rust processing is exercised through a substituted picker at desktop and 390px dark/200% text. Preview metrics state actual saved pixels, bytes, DPI and rounded mm; technical validation/metadata details are collapsed. A header overflow found at 200% was fixed with wrapping, and the success glyph was replaced by a labelled Material icon. Captures were visually inspected locally; OS-dialog, printer and representative-user testing remain open.

Scanner heuristic and actual workflow review (2026-10-18): import three page images → move page up → rotate selected page → prepare PDF → inspect page count/preview → save a Bangla-named copy. Reordering now preserves the selected source; edits update a bounded preview automatically, removing a separate Apply button. Full-resolution adjusted PNGs are no longer retained per page. The native/widget test passes at desktop light and 390px dark/200% text using bundled fonts, and waits for actual decoded PDF preview pixels before accepting the result. Page renders match the reordered edit settings. The new test found and corrected a page-appearance dropdown overflow. Capture-only results were visually inspected locally; no golden baseline or real-user time measurement is implied. Optional diagnostic captures: set UST_CAPTURE_SCAN to an existing private output folder and run test/scan_workflow_test.dart. No screenshots are uploaded by CI. Android camera/SAF/transport behavior and screen-reader/keyboard traversal remain device/user acceptance gates.

Print-sheet heuristic review: choose photo → set physical photo size/copies → choose standard/custom paper → optionally expand margins/spacing/resampling → preview PDF → save copy. Source pixels are retained by default. Invalid cutting-guide spacing shows a field error and keeps the chosen photo/settings; preparing opens advanced controls when validation fails. Real native workflows, bundled fonts and actual decoded PDF preview pixels pass at desktop light and 390px dark/200% text. Saved PDF geometry is checked independently with pypdf and rendered by Poppler. Actual-size instructions are visible before export. OS printing, representative users and screen-reader traversal remain unverified.
