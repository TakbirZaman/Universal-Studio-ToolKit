# Custom application packs and session sources

2026-10-21. Editable pack presets are declarative requirements, never code or official acceptance guarantees. Presets contain names, revisions, optional source text and up to 32 required/optional slots. Each editor slot selects one JPEG/PNG/PDF output, a safe filename, exact image pixels, optional strict KiB limit and PDF page range. Image preparation uses contain/padding, the existing bounded encoder and metadata policy. PDF preparation preserves the supported conservative structure policy. Unsupported constraints and impossible limits fail without saving a partial ZIP.

The native boundary bounds preset JSON to 64 KiB and aggregate source bytes to 64 MiB. Every ZIP document is reopened, measured and hashed using the existing exporter, with a manifest and validation report. Empty source bytes explicitly omit optional slots; missing required sources and processing/constraint failures identify the slot. Settings can be exported/imported as validated JSON without source bytes. Existing paths are never overwritten. The CLI accepts operation `pack`, a preset path and ordered inputs with null for omitted slots.

Prepared studio/recipe outputs can be explicitly copied into a session document collection for direct selection in application packs. The collection owns its bytes, returns defensive copies and bounds retention to 16 items/64 MiB. Individual removal, clear-all and process exit release collection references. This is session memory retention, not persistent signature storage, memory zeroization or a process-wide memory isolation guarantee. Selecting a session item creates an independently owned workspace source.

The generic pack core also supports validating already prepared outputs. The editor intentionally accepts only a single output format and strict KiB limits; it must reject imported settings it cannot faithfully represent. No face processing, signature background removal, arbitrary recipes, folder export, persistent source references or selective native retries are inferred from this slice.

Validation: native tests exercise actual archive measurements/hash checks, optional omission, required/bad input recovery, page limits, preset parsing and filename protection. An independent CLI run reopens the ZIP and checks exact entries, dimensions, byte limit, SHA-256 and no overwrite. Hosted generation and Flutter workflow checks are required before integration. Local Flutter execution was blocked by automatic approval review after SDK setup contacted a cloud metadata endpoint; it was not retried through an alternate route.
