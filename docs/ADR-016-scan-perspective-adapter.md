# ADR016 — pixel-only OpenCV scanner geometry

Status: work/scan-perspective development candidate. Source pinned, minimal Linux SDK and adapter built; independent synthetic pixel checks pass; no scanner geometry completion or platform claim. Not in saved application downloads.

Use an independently loadable C++ adapter with a narrow C ABI over already decoded RGBA pixels. Its only planned entry points are ABI/version checks, four-corner perspective warp and advisory document-edge suggestions. Rust owns input/output buffers, dimension/corner validation, scheduling and exports. No native file, camera, codec, model, network or scripting entry point is exposed.

Pin OpenCV5.0.0 to upstream commit40738fb16ceddb5fb3fea747585f7ce6abb0605b and archive SHA-25623affb17b8f7a46517a62b5e9fa637a8bc660acb5460bef9f130ee939df01ebb. The official release is stable; primary sources are https://github.com/opencv/opencv/releases/tag/5.0.0 and its pinned source. Root license is Apache-2.0; mandatory transitive modules and native dependencies require separate notice review before application staging. Selecting core/imgproc in5.0 also builds mandatory geometry/flann modules and bundled zlib. Do not infer their complete obligations from the root license.

Disable optional hardware, parallel, codec, GUI, external-engine and model integrations. The current source build configuration reports no parallel backend and zlib as its third-party dependency. A generic upstream download-initialization message is not evidence of a downloaded asset; inspect actual configure/build logs before staging. Build tools and source provisioning are developer operations. Normal application processing must never fetch assets.

Planned geometry uses normalized coordinates on the oriented original before quarter rotation, validates a clockwise convex quadrilateral, maps pixel centres correctly and limits input/output to24MP/12000px sides. Corrections remain per-page non-destructive edits. Suggested edges require review and explicit application. OpenCV failure returns a bounded error code; no document content/path is passed to C++.

Linux native verification: exact identity pixels, perspective samples compared with an independent NumPy homography (maximum gradient error0.736/255), original unchanged, invalid arguments leave output unchanged, blank images return no suggestion, and a synthetic page boundary is found within the measured tolerance. This proves only the native adapter slice. Next retain all applicable notices/provenance, add typed Rust models/validation/FFI and actual image/PDF tests. Regenerate bindings before exposing a responsive accessible corner editor. Add draft schema compatibility and verify Windows/Android builds, native dependencies, ABI/page alignment and device behavior separately.

The first5.0 build exposed its geometry-header split: add opencv2/geometry.hpp and the explicit geometry component. The tested shared adapter is4503976 bytes with SHA-2562a0949fc020400463a23ead1da9c51d18d7945526d0e78775068a153e115152a. ldd resolves only the host C/C++/math/compiler runtimes. Windows/Android builds, Rust integration, editor and distribution/license staging are not implemented yet. See evidence/vision-adapter-linux-20261019.json.
