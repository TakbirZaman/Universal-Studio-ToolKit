# Orientation-aware visual photo cropping

2026-10-21. The crop editor feeds the existing version2 crop recipe step. Bounds use orientation-corrected original pixel edges, before resizing. Original bytes are retained. A guarded native dimension query and bounded native PNG preview use the same decoder/ICC/resource policy as export; untrusted original image bytes never go directly to the Flutter image decoder.

The selection supports two48-pixel corner targets, movement of the selected rectangle, bounded undo/full-image reset, free/1:1/3:4/4:3/35:45 aspect choices and exact integer pixel fields. Focused handles accept arrow keys and Shift for ten-pixel steps. Dragging accumulates from the original pointer/selection so small movements are not lost through repeated integer rounding. Aspect constraints allow a one-pixel rounding tolerance. The primary action remains outside the scrolling editor and is unavailable until the canonical preview has decoded.

Photo Studio can pass its selected original directly to the crop/recipe workflow; no intermediate user export/import is required. Recipes can also open the editor after source selection. Accepting a crop updates only the declarative coordinates and invalidates any prior prepared result. Cancelling the editor leaves the existing recipe unchanged. Actual export redecodes and crops the original through Rust, never the display thumbnail. This editor does not add face detection, destructive editing, general signature masks or inherited rotation/physical-unit settings from another workspace.

Native tests compare every exported PNG pixel against a source crop, verify EXIF orientation, reject out-of-bounds coordinates/invalid bytes and preserve sources. Geometry property tests cover bounds, opposite-corner anchoring and aspect locks. Hosted UI tests exercise drag, keyboard, aspect selection, coordinate recovery, cancellation and actual saved dimensions at100%/200% text. The candidate must pass generated-bridge and complete platform checks before integration.
