# Known limitations — not launch complete

Current source includes flexible photo compression, visual cropping, custom application packs, bounded session document reuse, saved-copy actions, scan geometry/manual straightening, physical print layouts, existing PDF text extraction and PDF overlays. Exact tested revisions are recorded in PROJECT_STATUS.md and CHECKPOINT.md. Older delivered installers may precede these features; a source merge or hosted artifact does not replace a previously saved installer.

- Windows x64, Linux x64 and Android ARM64 development builds have hosted verification. Clean-device installation, complete interactive workflows, Android camera/gallery/provider/activity recreation, external viewers, screen readers and printers still require acceptance. Hosted desktop window launch is not a substitute for these checks. Android development packages use disposable signing identities; stable private signing and backup remain outstanding.
- PDF operations retain supported text/vector content, but reject protected PDFs and unsupported forms, annotations, bookmarks, attachments, signatures, actions, optional content and tagged structures. Watermarks currently accept visible ASCII only. Text extraction may miss glyphs or differ from visual reading order; it is bounded to one million counted characters and 4 MiB of saved UTF-8. Image-only scans need separately available OCR. There is no general appearance/interoperability guarantee for arbitrary PDFs.
- Native parsing is in-process. Encoded-size, page-count, object-count and nesting checks do not provide hard protection against decompression bombs or parser resource exhaustion. Worker isolation, application-wide memory/time budgets and adversarial parser coverage remain production work. Sequential processing and retained-output quotas do not cap all decoded buffers, PDF objects and bridge copies.
- Photo inputs are JPEG/PNG, up to 24 megapixels/64 MiB. ICC profiles are rejected rather than silently changed; unprofiled pixels are assumed sRGB. PNG gamma/chromaticity and complete colour interoperability need validation. Flexible compression tests at most nine explicitly approved sizes and chooses the largest valid sampled dimensions; this is not a proven global maximum. Cancellation waits for the active photo's bounded search. Visual crop coordinates refer to the orientation-corrected original before resizing; no face-assisted crop suggestions are implemented.
- Signature background removal uses a brightness threshold for plain backgrounds. Manual mask refinement, consented reusable signature storage/deletion and visual PDF placement remain unfinished. No physical secure-erasure promise is made.
- Scanner geometry uses the explicitly bundled OpenCV adapter. Corner suggestions and quality warnings are advisory. Manual straightening is limited to ±10° relative outline adjustment and can crop edges when keeping the outline inside the source. Review fine text and boundaries. Automatic angle detection, curved-page dewarping and glare/shadow removal are not implemented. Android system-camera capture compiles but still needs device validation; save a scan draft before capture.
- Linux OCR requires the separately installed `/usr/bin/tesseract` and verified English/Bangla models. Windows/Android offline engine packaging, searchable-PDF geometry/reading order and representative accuracy/performance validation remain unfinished. OCR child limits do not establish a filesystem/network sandbox or cap all parent-side image preparation. Cancellation kills/reaps the engine before returning, but abnormal parent termination can leave private temporary files; abandoned-job cleanup remains outstanding.
- Custom application presets are user-supplied requirements, not official compliance certification. Current slots support one JPEG/PNG/PDF output format, exact image pixels and strict byte/page limits. Image preparation uses fit/padding; signature cleanup is separate. Broader slot policies/recipes, folder export and pack-specific selective retries remain. Session documents are explicitly retained owned copies, limited to 16 items/64 MiB with remove/clear controls; persistent managed sources are not implemented. The separate preset catalogue stores requirement settings only (including names and requirements-source text), requires explicit saving, supports confirmed deletion and rejects changed values with an existing exact name. It is not encrypted secret storage and deletion is not physical secure erasure.
- Save-copy names are validated and desktop exports do not overwrite existing files. Unicode normalization/case collisions, provider partial writes and all filesystem/provider behaviors need more coverage. Android content URIs are not filesystem paths; provider-renamed display names and recreation need further work.
- Open/share/reveal requests do not prove an external viewer succeeded. Desktop systems need compatible utilities and associations. Android handoffs use current-Activity verified URI receipts in a bounded 128-entry memory map; recreation discards that map. External applications have their own privacy/network behavior. Unsupported controls are hidden.
- Physical photo/print exports support validated paper sizes, margins, spacing, copies, guides and optional explicit resampling, with actual-size instructions. Rounding and external printer settings can change measured dimensions; physical printer and official-application acceptance are unverified.
- Localization/Bangla interface, complete keyboard/reduced-motion/system-scaling and representative-user/screen-reader acceptance remain. Existing 100%/200% workflow tests cover specific journeys, not all controls or devices.
- Complete native/transitive license obligations, clean-device redistribution checks, AppImage packaging where practical and durable installer delivery remain outstanding. Collected notices are not complete legal clearance.
- Secure redaction, encryption/unlocking, certificate-backed signing, general Word conversion, remote AI/cloud synchronization and payments are deferred and are not functioning features.
