# Explicit local application-preset catalogue

2026-10-22. Custom application packs can explicitly save their requirements in the existing local SQLite database, reopen a catalogue, load a preset and delete it. Saving is opt-in for each preset; importing, editing and processing documents do not automatically persist a preset. JSON import/export remains available when local storage is unavailable. Portable mode uses the existing selected application-data directory.

The stored value is the strictly parsed PackPreset schema: name, revision, optional requirements-source text, verification flag and document-slot requirements. It never includes selected document bytes or selected source locations. Names and requirements-source text may themselves be personal data and are retained until deletion. Loading replaces editor settings and clears selected sources. Deleting a saved preset leaves the current editor, session document store, originals and exported files unchanged. The interface offers a deletion confirmation and cancellation; deletion is logical removal, not secure physical erasure.

Each canonical JSON value is limited to 64 KiB; the catalogue is limited to 64 entries and 4 MiB in aggregate. SQLite IMMEDIATE transactions serialize quota checks and insertion across writers. Saving an identical existing value is idempotent. A changed value with an existing exact name is rejected, requiring renaming or explicit deletion first; there is no silent replacement. Identity is the exact stored name, with SQLite NOCASE/name ordering for display, not a promise of Unicode-equivalent-name normalization. Bound SQL parameters preserve Bangla, apostrophes and SQL-like text safely.

Reading checks aggregate limits, parses and validates every entry, and rejects malformed values or key/value identity mismatches without deleting or rewriting them. It reports storage failures rather than returning a fabricated empty catalogue. Existing database schema version1 already has the presets table, so no destructive migration is required. The database is local settings storage, not encrypted secret storage or managed persistent document storage.

Native tests cover restart persistence, Bangla/SQL-like names, unchanged-value saves, changed-value collision protection, deletion, simultaneous writers and quota recovery, unknown document payloads, malformed/oversized JSON, corrupt records and identity mismatch. Hosted UI tests exercise real SQLite save/restart/load/delete, deletion cancellation, selected-source exclusion and unavailable-storage recovery at100%/200% text. Generated bindings and complete platform checks must pass before integration. Real-device backup/permissions, clean-system and screen-reader acceptance remain separate release work.
