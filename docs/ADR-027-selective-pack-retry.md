# Independent application-pack preparation and retry

24 October 2026. Custom application packs prepare document slots independently and retain successful results while other sources fail. The default prepare action processes unfinished selected/required slots, then assembles a ZIP only when every selected or required document has a valid result. A selected optional document that fails is not silently omitted: repair it or explicitly clear its source. Empty optional slots remain explicit omissions.

The native prepare-slot boundary validates the full preset, processes the selected source and reopens the output to check format, dimensions, bytes and PDF pages. The native cached-build boundary bounds the result count/aggregate bytes and reopens every prepared document before applying current slot constraints and assembling the verified ZIP. Cached documents are archived byte-for-byte, without JPEG recompression. Caller-supplied validation strings are not trusted as proof. Existing all-at-once native/CLI operations remain compatible.

Each editor slot owns its result, source reference, raw settings fingerprint and error. A source or slot-setting change invalidates that slot; other results survive. Global preset metadata changes invalidate the archive but retain unchanged document results. Loading another preset disposes the old slots and results. Sources and retained prepared results each have a64 MiB aggregate bound. These encoded-byte quotas do not provide process-wide memory isolation; source/result/archive/decoder/bridge copies can coexist.

Stop waits for the active native operation, keeps its successful result and skips later operations. Resume skips ready slots. Navigation is blocked during preparation, controls are disabled, and changed/stale settings are checked again before retaining results and assembling the archive. This is checkpoint cancellation, not interruption of a decoder or hard real-time cancellation. Retained documents are session-only; saved preset JSON contains requirements only.

Native tests verify a failed peer can be repaired without changing successful encoded bytes, optional omission, page constraints and slot bounds, stale constraints, forged metadata, corrupted bytes and an aggregate budget rejection before decode. Hosted UI tests call the real engine through an observing service to count processing calls: failed retry and source repair never reprocess the successful peer; editing one slot reprocesses only it; stop/resume retains the completed result. Tests at100%/200% text save an actual ZIP and reopen/validate it. Complete platform, bridge and existing workflow checks gate integration. This does not complete per-slot recipes, folder export, persistent managed documents or launch acceptance.
